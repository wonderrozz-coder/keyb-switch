# Устройство программы

Документ для тех, кто будет читать или менять код.

## Структура

```
kbswitch/
├── cli.py            разбор команд, вывод, doctor, dict, setup
├── daemon.py         главный цикл: select() по клавиатурам, IPC-сервер, сигналы
├── engine.py         сердце: буфер слова, решение, коррекция, live, двойной Shift
├── layout.py         ctypes-обёртка libxkbcommon: «символ ↔ код клавиши + shift»
├── dictionaries.py   libhunspell через ctypes + резервный список слов
├── frequency.py      частотные ранги, индекс опечаток «на одну клавишу»
├── prefixes.py       статистика трёхбуквенных префиксов (тайбрейкер)
├── selection.py      чтение/запись выделения (primary selection Wayland)
├── inject.py         вставка текста через wtype
├── reader.py         перечисление и мультиплексирование клавиатур
├── hypr.py           Hyprland IPC (сокет, JSON через префикс "j/")
├── watcher.py        событийный сокет Hyprland, кеш окна и раскладки
├── ipc.py            Unix-сокет CLI ↔ демон
├── config.py         TOML-конфиг и значения по умолчанию
└── dictsetup.py      скачивание словарей
```

## Поток события

1. `daemon.py` держит `select()` на всех `/dev/input/event*` с буквами A–Z.
   Устройства пересканируются каждые 3 секунды (горячее подключение).
2. Каждое `EV_KEY` уходит в `Engine.handle_key(code, value)`.
3. Движок обновляет набор зажатых клавиш и решает, что делать с символом.

`value`: `1` — нажатие, `0` — отпускание, `2` — автоповтор.

## Классификация клавиш

| Категория | Поведение |
| --- | --- |
| буквы | добавляются в буфер слова |
| цифры и пунктуация | **добавляются в буфер** — `,` в русской раскладке это `б`, и `nt,z` = `тебя` |
| пробел, Enter | слово закончено → проверка → перепечатываются вместе со словом |
| Tab | слово закончено, но не перепечатывается (смена фокуса) |
| стрелки, Home/End, Esc, PgUp/PgDn, Insert, Delete | буфер сбрасывается |
| Shift, Alt, AltGr, CapsLock | только модификаторы |
| Ctrl, Super | буфер сбрасывается: это шорткат, а не текст |

## Решение «в какой раскладке это слово»

Ядро — `Engine._judge(word, group, other)`. Оно **сравнивает доказательства**
для двух кандидатов, а не проверяет «существует ли слово»:

```python
вес = 3  слово в топ-4000 частотного списка
      2  слово в топ-20000
      1  легальная форма по словарю, но не в списке
      0  неизвестно
```

Порядок принятия решения:

1. **Опечатка?** Если буфер на одну клавишу отстоит от частого слова
   *текущего* языка — это опечатка, не трогаем. Но только если кандидат
   в другой раскладке не частотнее (иначе `ерфе` → `that` не сработало бы).
2. **Вес второй раскладки выше** → переключаем.
3. **Равенство, оба слабые** → спрашиваем статистику префиксов.
4. Иначе — не трогаем (слово настоящее в обеих раскладках, например `here`).

Почему так, а не «словарь сказал да/нет»: словарь отвечает «это допустимая
форма?», а нам нужно «это правдоподобное слово?». `еру` — легальный
родительный падеж от «ерунда», но `the` правдоподобнее. Подробнее с замерами:
`docs/MEASUREMENTS.md`.

## Исправление текста

Инъекция идёт через `wtype` (протокол Wayland virtual-keyboard), а не через
свой uinput. Причины:

- `wtype` **не зависит от активной xkb-группы** — символы отправляются как есть,
  поэтому не нужно временно переключать раскладку для печати;
- его нажатия не попадают в наш evdev-читатель → нет зацикливания;
- любые Unicode-символы вставляются корректно.

Схема замены: `wtype -k BackSpace × N` + `wtype -- "<текст>"` одной командой.

**Порядок важен:** приложение уже получило разделитель (пробел/запятую),
вызвавший проверку, поэтому он тоже удаляется и печатается заново.

## Три уровня двойного Shift

1. **Есть выделение** → читаем primary selection (`wl-paste --primary`),
   конвертируем, пишем обратно (`wl-copy --primary`), переключаем раскладку.
2. **Буфер не пуст** → конвертируем набираемое слово.
3. **Буфер пуст** → последнее слово, если набрано не позже `force_window_s`.

«Чистое» двойное нажатие: между двумя Shift не должно быть введено ни одного
символа, иначе это обычный набор заглавной буквы. Так же отсекаются
`Ctrl+Shift` (собственный переключатель раскладки пользователя).

Уровень 1 требует, чтобы выделение вообще существовало (приложение публикует
primary selection). Если приложение заменить его не дало — срабатывает
уровень 2, ввод не ломается.

## Производительность

Главная находка при профилировке: `hunspell -a` как подпроцесс тратит
**40 мс** на незнакомое слово (генерирует варианты исправлений), а проверка
почти всегда включает незнакомое слово. Через `libhunspell` напрямую —
**0.003 мс**. Поэтому словари загружаются через ctypes, а не как процесс.

| операция | время |
| --- | --- |
| проверка слова (libhunspell) | 0.002–0.003 мс |
| полное решение по слову | 0.06 мс |
| сборка таблиц xkb | ~25 мс при старте |
| построение статистики префиксов | 0.5 с один раз, далее кеш |

## Точки расширения

- **Новая раскладка** — ничего делать не нужно: таблицы компилируются из
  живого keymap Hyprland (`input:kb_layout`). Нужен только словарь;
  соответствие имён — `dictionaries.DICT_ALIASES`.
- **Новый язык для статистики** — добавить URL в `prefixes.FREQUENCY_URLS`
  и код языка в `frequency.LANG_OF_DICT`.
- **Другой композитор** — заменить `hypr.py` (сейчас Hyprland IPC) и
  `inject.py` (нужен протокол virtual-keyboard).
- **Другая политика решения** — одно место: `Engine._judge`.
